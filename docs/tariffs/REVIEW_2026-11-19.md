# C6 Tariff Monitor: adversarial review, 2026-11-19

This review was read-only. The C6, parser and C2-signal test suites pass; the database paths were checked by reading the code.

"Confirmed" means one of three things:
- the reviewer reproduced it with a script;
- a second reader checked the code (marked †);
- or the bug is plain from the code.

None of these are fixed yet. **Fix them in the order of the "Priority" column.**

**Checked and found correct:**
- inclusive `valid_to` and membership end dates;
- the US "entered before" rule;
- relative preferences;
- unresolved stacked surcharges;
- category exemptions;
- column-2 scope;
- `E*` partial eligibility listed rather than applied;
- the stale-MFN fallback, flagged;
- ceilings;
- diffs only within the same parser version;
- deterministic change ids;
- idempotent `write_rates`;
- `mark_current` per (source, scope);
- path-parameter validation;
- bounded list limits;
- server-only API calls;
- User-Agent and throttling;
- matrix and product badges.

**Analysis.** The engine's core rules hold up. The real risks sit at the edges:
- **How unresolved values are worded in the UI (#1, #10).** This is the most visible issue in a demo: "≥ 12 %" for a Bangladeshi product that probably pays 0 % in the UK contradicts the "never guess" rule.
- **What counts as a change, and as confirmation of a news story (#2, #7, #9).** This affects the "in the schedule" chip.
- **Rules the parser captures but the engine drops (#3, #12).**

Suggested fix scope: #1–#4 and #8 are small (each under an hour, with tests). #5 to #7 and #9 are medium. #11 to #14 can wait until after the demo.
